1 · Transaction ownership — take commit() back from the UI

✓ Complete Strong in-process

work_items_tab.py:163–228 (7 sites) · saved_nwas_tab.py:69–99 (3) · settings_reports_tab.py:72–79 (2) · services/*

Problem. Every tracking, work item and NWA module mutates the DB but never commits — the durability invariant lives in 12 UI handlers, and every test of the tracking module must also know to commit.

Solution. Move durability behind the tracking and repository modules' interfaces: the seam owns the transaction, so a handler is one call.

One missed commit = silent data loss on close. Tests must repeat the ritual.

▼ interface

tracking / repository modules

start_or_switch · update_session · move_work_item

12 → 0 commit sites. Delete the invariant from every caller.

  • Locality: durability concentrates in one module

  • Tests exercise the interface as callers do — no commit in setup
  • Tracking module's interface stops hiding a "not durable yet" caveat

3 · Dialog intake seam — dialogs become thin Tk adapters

Strong local-substitutable

ui/dialogs.py (256 LOC) · services/validation.py · work_items_tab.py:154–180 · saved_nwas_tab.py:63–90

Problem. The form→domain-draft conversion is the real module, but it's trapped inside Tk constructors: dialogs query the DB in __init__ (dialogs.py:126, 143, 217), duplicate service validation ("code required" exists in both NwaDialog.validate and repository.save_nwa), stash parse side-effects on self._parsed_* with a hidden run-order invariant, and wait_window() in the constructor makes any of it untestable without a live Tk loop.

Solution. Extract pure validate(form) → draft functions behind a seam; dialogs shrink to adapters that collect fields and render errors. Split-sum validation stops surfacing from two modules at two different times (pre-close vs post-close). Options passed in, not re-queried.

4 · Repository interface is "the DB, renamed"

Worth exploring in-process

services/repository.py (255 LOC, 16 functions) · work_items_tab.py:97 · dialogs.py:69–72, 141–145, 228–233

Problem. The interface is nearly 1:1 with the SQL: 16 functions returning raw rows. Callers must know the GROUP_CONCAT tags artifact, basis-point units, is_deleted flags, and the sort_order ordering that move_work_item silently depends on. Proof of leak: work_items_tab.py:97 hand-rolls a second bp→percent formatter that disagrees with validation.basis_points_to_percent (50 bp renders as "0%" there, "0.50%" here).

Solution. Narrow the interface to domain-shaped returns — percent strings, tag lists, ordered item drafts — and let the implementation absorb the SQL artifacts. Several members fail the deletion test (get_setting, remove_*, get_work_item are pass-throughs); the deepening absorbs them.

5 · Invariant holes the deepened seams would expose

Speculative rides along with 1–3

services/tracking.py:131–133 · services/repository.py:209–223 · tests/test_phase1_safety.py

Problem. Two domain invariants are only half-enforced. update_session(end_at=None) on a closed session silently re-opens it — the one-open-session invariant lives only in start_or_switch; current_open_session's LIMIT 1 masks violations instead of preventing them. Solution. Not a standalone refactor: once candidates 1–3 give a testable interface, pin both invariants with tests through the tracking module's interface, and give move_work_item one failure protocol instead of two.

6 · paths.py — getters that mkdir
